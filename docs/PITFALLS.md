## 로컬은 통과하는데 CI와 배포에서만 빌드가 죽는다

**로컬 `node_modules`가 커밋되지 않은 상태를 메워 주고 있기 때문이다.** 개발 기계에는
다른 패키지를 빌드하며 깔린 것들이 남아 있고, CI는 매번 빈 상태에서 시작한다.
그 격차가 곧 원인이다.

**모노레포에서 가장 흔한 형태는 옆 패키지 파일을 직접 import할 때다.** 예를 들어
`brand/src/.../HeroTrail.jsx`가 `../../../arena/.../trail.js`를 부르면,
그 arena 파일 안의 `import * as THREE from 'three'`는 **arena 폴더 기준으로 해석**돼
`arena/node_modules/three`를 찾는다. 개발 기계에는 그게 있고 clean 체크아웃에는 없다.

```
Error: [vite]: Rolldown failed to resolve import "three" from ".../arena/.../trail.js"
```

**해결은 dedupe다.** 부르는 쪽 vite 설정에 넣으면 bare specifier가 그 프로젝트 기준 한 벌로 모인다.

```js
resolve: { dedupe: ['three'] }
```

덤으로 `Multiple instances of Three.js being imported` 경고도 사라진다. 두 폴더가 각자 한 벌씩
물던 것이 한 벌이 되기 때문이다(실측: 번들 1084KB에서 926KB로 줄었다).

**확인 규율. 로컬 빌드 통과를 완료 근거로 쓰지 않는다.** 커밋된 것만으로 빌드해야 한다.

```
git archive HEAD | tar -x -C /tmp/clean       # 커밋된 파일만
cd /tmp/clean/<앱> && npm ci && npm run build
```

**앱을 여러 개 검사할 때는 각각 따로 푼 트리에서 돌린다.** 한 트리에서 이어 돌리면
앞 앱의 `npm ci`가 옆 폴더에 `node_modules`를 만들어 뒤 앱이 그 덕을 본다.
**이 오염 때문에 한 번 통과로 잘못 읽을 뻔했다**(격리해서 다시 재니 진짜 상태가 나왔다).

**대소문자는 별개 원인이고 별도로 검사한다.** 맥과 윈도우는 파일명 대소문자를 무시하고
리눅스는 구분한다. `git ls-files`가 아는 경로와 import 문자열을 바이트 단위로 대조하면
실제로 위험한 것만 걸러진다(`?url` 같은 쿼리 접미사는 떼고 비교해야 오탐이 안 난다).

## 배포본이 리포보다 낡았을 때 (버그로 오진하기 쉽다)

배포 화면에서 이상한 것을 보면 **먼저 그 배포본이 지금 코드인지 확인한다.** 코드는 이미 고쳐졌는데
배포가 안 따라온 것이면 소스를 아무리 봐도 원인이 안 나온다. 없는 버그를 고치려다 멀쩡한 코드를 망친다.

**확인법. 번들 문자열을 직접 찍는다.** 배포된 `index.html`이 참조하는 자산을 받아
버전을 가르는 문구가 있는지 본다. 화면을 보는 것보다 빠르고 확실하다.

```
curl -s https://<배포주소>/ -o dep.html
grep -oE '(src|href)="[^"]+"' dep.html          # 참조 자산 전량. head -1로 자르지 마라
curl -s https://<배포주소>/assets/<번들>.js -o dep.js
grep -c "최근에 넣은 문구" dep.js                # 0이면 그 커밋이 배포에 없다
```

**언제 들어오고 나갔는지는 `git log -S`가 답한다.** 배포본에 있는 문구와 없는 문구를 각각 넣어
구간을 좁히면 배포본의 커밋 시점이 나온다.

```
git log --oneline -S '배포본에 남아 있는 문구' -- <파일>
git log --oneline -S '배포본에 없는 문구' -- <파일>
```

**함정. SPA rewrite 때문에 HTTP 상태 코드는 증거가 안 된다.** `vercel.json`의
`{"source": "/(.*)", "destination": "/index.html"}`이 **없는 경로까지 200으로 index.html을 준다.**
`/licenses/.../NOTICE`가 200이라고 그 파일이 배포에 있는 것이 아니다(실제로 이걸로 한 번 오진할 뻔했다).
파일 존재를 확인하려면 **상태 코드가 아니라 본문**을 봐야 한다. 본문이 `<!doctype html>`이면 없는 것이다.

**증상이 여럿이어도 뿌리는 하나일 수 있다.** 서로 다른 화면 셋이 동시에 틀렸다면
개별 버그 셋이 아니라 배포 하나가 낡은 것을 먼저 의심한다.

## 문턱을 필터 뒤에서 재면 사용자가 실제로 내야 하는 값은 그 몇 배다

**센서 값에 평활을 걸고 그 뒤에서 임계를 비교하면, 임계 숫자는 더 이상 사람이 낸 크기가 아니다.**
필터가 얼마나 깎는지는 신호의 길이에 달렸고, 짧고 날카로운 동작일수록 많이 깎인다.
코드에는 "18"이라고 적혀 있는데 손은 37을 내야 하는 상황이 조용히 만들어진다.

간합에서 실제로 이랬다. 찌르기 감지가 `acc += (lin - acc) * 0.2`(60Hz, 시정수 약 83ms)를
거친 값을 임계 18과 비교했다. 120ms짜리 찌르기 펄스는 이 EMA를 지나며 **원 피크의 56%**가 된다.

```
지속 120ms 펄스   원 피크 15 -> 8.3 (56%)   20 -> 11.1   30 -> 16.7
지속  80ms 펄스   원 피크 15 -> 6.5 (43%)    짧을수록 더 깎인다
```

즉 임계 18은 **원 피크 37 m/s^2 = 3.8G**를 요구했다. 손목으로 낼 수 있는 값이 아니라
팔을 휘둘러야 나오는 값이고, 증상은 "몇 판 만에 지쳐서 테스트조차 못 하겠다"로 나타났다.
코드만 읽으면 18이 과해 보이지 않는다는 것이 이 함정의 핵심이다.

**방지책 셋.**

1. **임계를 정하기 전에 감쇠율을 먼저 잰다.** 합성 펄스를 여러 지속 시간으로 통과시켜
   원 피크 대비 몇 퍼센트가 남는지 표로 만든다. 그러면 임계를 사람 단위(G)로 환산할 수 있다.
2. **어느 관문이 실제로 막는지 따로 확인한다.** 간합의 경우 걷기와 고쳐잡기를 자르는 것은
   크기 관문이 아니라 **수평비와 최소지속**이었다. 크기를 18에서 8로 내려도
   오탐 시나리오 일곱 개 전부 0건이었다. 크기 관문은 오탐을 막는 대신 체력만 쓰고 있었다.
3. **화면에 값을 띄운다.** 임계와 같은 단위(평활 뒤 값)로 "최근 최대"를 붙들어 보여 주면
   사용자가 자기 동작 한 번으로 자기 값을 읽는다. 추측으로 튜닝하는 왕복이 사라진다.

## null로 되돌려 이펙트를 재발화시키면 그 이펙트의 복귀 타이머가 죽는다

**같은 값이 연달아 와도 애니메이션을 다시 돌리고 싶을 때 흔히 쓰는 수법이 있다.**
값을 넣었다가 곧바로 `null`로 되돌려 의존성을 흔드는 것이다. 이것이
**스스로 꺼지는 이펙트와 만나면 영구히 켜진 상태로 굳는다.**

```jsx
// 부모
setFlash('hit');
setTimeout(() => setFlash(null), 10);   // 재발화용 되돌리기

// 자식
useEffect(() => {
  if (!pattern) return undefined;        // <- null이면 여기서 끝난다
  setOn(pattern);
  const t = setTimeout(() => setOn(null), 140);
  return () => clearTimeout(t);          // <- null이 오면 이 정리가 먼저 돈다
}, [pattern]);
```

순서를 따라가면 원인이 보인다. 10ms 뒤 `null`이 들어오면 React가 **먼저 이전 실행의
정리 함수를 부르고**(140ms 복귀 타이머가 여기서 죽는다) 새 실행은 조기 반환한다.
`setOn(null)`에 닿는 길이 통째로 사라져서 화면이 그 색으로 남는다.
**끄는 코드가 분명히 있는데 안 꺼지므로 그 줄만 들여다보면 원인이 안 나온다.**

**방지책 둘.**

1. **재발화는 값이 아니라 정체성으로 시킨다.** `{ pattern, id }`처럼 매번 새 객체를 낸다.
   같은 패턴이 연달아 와도 의존성이 바뀌고, `null`로 되돌릴 이유 자체가 없어진다.
2. **이펙트에 조기 반환을 두지 않는다.** 입력 하나에서 상태를 통째로 결정하게 쓴다.
   그러면 `null`이 들어와도 그 자리에서 꺼진다(리셋 경로가 공짜로 생긴다).

```jsx
useEffect(() => {
  setOn(flash ? flash.pattern : null);   // 조기 반환 없음. flash가 on을 통째로 결정한다
  if (!flash) return undefined;
  const t = setTimeout(() => setOn(null), 140);
  return () => clearTimeout(t);
}, [flash]);
```

**확인법. 시간을 두고 계산값을 여러 번 읽는다.** 한 번만 보면 "떴다"까지밖에 못 본다.
직후와 500ms 뒤와 3초 뒤를 각각 재면 자동 복귀가 실제로 도는지가 그 자리에서 갈린다
(실측으로 수정 전은 세 시점 모두 `rgb(230,13,21) 0.55`였고 수정 후는 뒤 둘이 사라졌다).

## 인라인 style이 CSS를 이긴다 (media query, :hover, :active)

**요소의 `style` 속성은 스타일시트의 어떤 선택자보다 세다.** 그래서 인라인으로 값을 걸어 두면
그 속성을 건드리는 media query와 의사 클래스 규칙이 통째로 죽는다. 규칙이 사라진 것이 아니라
계속 지고 있는 것이라 CSS만 들여다보면 원인이 안 보인다.

간합에서 **세 번 나왔다.**

1. arena `Button.jsx`가 `background`를 인라인으로 걸어 `.ganhap-btn-primary:active`의
   `--red-press`가 한 번도 그려지지 않았다. press 토큰이 생긴 이래 계속 죽어 있었다
2. brand CTA를 만들 때 같은 함정을 예방하려고 채움을 `.vx-cta` 클래스로 옮겼다
3. brand `Header.jsx`가 `<nav style={{display:'flex'}}>`로 걸어
   `@media (max-width: 767px) { .vx-nav { display: none } }`가 죽었다. 320에서 메뉴가 안 접혔다

**방지책.** CSS가 상태나 폭에 따라 바꿔야 하는 속성은 인라인에 두지 않는다. 대상은 주로
`display`, `background`, `color`, `transform`, `opacity`다. 컴포넌트는 클래스 이름만 주고
값은 스타일시트가 쥔다. 색을 하드코딩하지 않기 위해 토큰을 CSS 변수로 주입하고 CSS가 그 변수를 읽는다.

**한 요소의 `display`는 정확히 한 클래스에만 둔다.** 바용과 시트용처럼 쓰임이 갈리면
클래스를 나눈다(`.vx-cta-bar`, `.vx-cta-sheet`). 공용 클래스 하나에 `display`를 두고
다른 미디어쿼리로 덮으면 선언 순서에 기대게 되어 다시 깨진다.

**진단.** 화면에서 계산된 값을 직접 읽는다. 규칙이 존재하는데 계산값이 안 바뀌면 인라인을 의심한다.
브라우저에서 인라인 속성만 지워 보면 그 자리에서 원래 규칙이 살아난다.

## z-index 위계

모달·오버레이·드롭다운·헤더·토스트의 층위를 tokens에 수치로 정의한다. 모달이 헤더 뒤로 가는 사고는 위계표가 없어서 생긴다.

권장 스케일: 콘텐츠 0 / sticky 요소 10 / 드롭다운 30 / 헤더 50 / 오버레이·딤 90 / 모달 100 / 토스트 110.

모달은 딤 스크림(fixed inset-0)과 패널을 함께 최상위로 올리고, body 스크롤을 잠근다.

## 서드파티 라이브러리 실패 모드

요소를 숨겼다가 되돌리는 방식(opacity·pointer-events 조작)의 라이브러리는 **실패 시 요소가 영구히 사라지거나 클릭 불가가 된다.**

- 핵심 UI(헤더·내비게이션)에는 이런 라이브러리를 쓰지 않거나, **실패해도 항상 보이는 상태가 기본값**이 되도록 방어한다.
- `pointer-events`는 상속되므로 부모에 걸면 자식 인터랙티브 요소 전체가 막힌다.
- "숨김 → 성공 시 복원" 순서인 라이브러리는 성공·실패 양쪽 경로 모두에서 복원을 호출한다.
- 초기화가 상태 변화마다 재실행되지 않게 의존성 배열을 점검한다(호버할 때마다 재초기화되면 매번 숨김부터 다시 시작한다).

## 브라우저별 검증

Chrome만 보고 끝내지 마라.

- **iOS Safari** — HTML5 드래그앤드롭을 지원하지 않으면서 `draggable="true"` 요소가 자식의 탭(click)을 삼킨다. 터치 기기에서는 `matchMedia('(pointer: coarse)')`로 감지해 `draggable`과 drag 핸들러를 아예 걸지 않는다.
- **Chromium 파생 브라우저(Whale 등)** — 캔버스·WebGL 타이밍이 Chrome과 다르다. WebGL 기반 효과는 실패 폴백이 반드시 있어야 한다.
- **동적 뷰포트** — iOS Safari의 주소창 때문에 `100vh`가 흔들린다. 모달·전체화면 요소는 `100dvh` 또는 JS 기반 높이 계산을 쓴다.

## 다국어 레이아웃 안정성

- 언어 전환 시 컴포넌트를 **리마운트하지 마라.** 등장 애니메이션이 재실행되어 화면이 깜빡인다.
- 텍스트만 교체하고, 길이 차이로 인한 레이아웃 시프트는 긴 언어 기준 `min-height` 예약으로 막는다.
- 전환 시 스크롤 위치를 유지한다.
- 헤더·메뉴 라벨은 활성 언어 하나만 렌더한다(국문·영문 동시 표기 금지).

## 목록·정렬

- 정렬 기준 필드가 비어 있을 때 id 순으로 뒤집히는 사고를 막기 위해 **명시적 타이브레이커**를 둔다.
- 페이지 크기 상한이 전체 목록을 잘라먹지 않는지 확인한다.
- 새로 등록한 항목이 의도한 위치(보통 최상단)에 오는지 실제로 등록해 검증한다.

## 업로드 경합

파일 업로드가 완료되기 전에 저장이 실행되면 URL이 빈 채로 기록된다.

- 업로드 성공 응답을 받은 뒤 저장하도록 순서를 보장한다.
- 실패 시 조용히 넘어가지 말고 사용자에게 알린다.
- 업로드 중 로딩 표시, 완료·실패 피드백을 제공한다.
- 저장 후 목록·상세가 최신 URL을 다시 읽는지 확인한다.

## 폼 입력

- 이메일은 형식 검증 후에만 제출 허용.
- 전화번호는 자동 하이픈 포맷팅으로 형식을 강제한다(그 외 문자는 입력 자체를 막는다).
- 비밀번호 확인 필드는 세로로 배치한다(가로 2열은 좁은 화면에서 깨진다).
- 짧은 라벨(3~4글자) 필드에 전체 너비를 주지 말고 2열 배치를 활용한다.
- 필수 항목이 비면 제출 버튼을 비활성화하고, 어느 항목이 비었는지 인라인으로 알린다.

## 네이티브 UI 노출

`<select>`, `<input type="date">`, `<input type="datetime-local">`, 기본 라디오·체크박스는 OS 기본 UI가 그대로 노출되어 디자인 시스템을 깨뜨린다. 커스텀 컴포넌트(드롭다운, 캘린더, 라디오 카드)로 대체하고, 코드베이스 전수 검색으로 잔존 0건을 확인한다.

## 배포·인프라

- **SPA 라우팅** — `client/vercel.json` rewrites가 없으면 새로고침·직접 진입 시 404가 난다.
- **cross-origin 쿠키** — 프론트와 백엔드 도메인이 다르면 `sameSite:'none'` + `secure` + `trust proxy` + `NODE_ENV=production`이 전부 필요하다.
- **CORS** — origin은 끝 슬래시 없이 정확히 일치해야 한다.
- **콜드 스타트** — 무료 티어 백엔드는 일정 시간 후 잠든다. 첫 요청이 실패하는 것처럼 보이므로 uptime 모니터를 두거나 로딩 상태를 명확히 표시한다.
- **환경 종속값** — 도메인·API 주소·토큰을 하드코딩하지 않는다. 계정·도메인 이전 시 값만 바꾸면 되게 한다.
- **OG 이미지** — 절대 URL(https)이어야 한다. 상대경로는 카카오 등 크롤러가 읽지 못한다. SPA는 크롤러가 JS를 실행하지 않으므로 라우트별 동적 메타가 반영되지 않는다(필요하면 프리렌더링 또는 서버리스 주입).

## 데이터 무결성

- **비파괴 시드** — TRUNCATE/DELETE 금지. 고유 키 + `ON CONFLICT DO NOTHING`, 기존값은 `COALESCE` 보호.
- **마이그레이션** — DROP 금지, `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`.
- **원문 보존** — 사용자 제공 텍스트는 `SOURCE.md`에 두고 문자 그대로 복사, 시드 후 표본 3건 문자 대조.
- **백업** — 구조 변경·계정 이전 전에는 항상 백업을 먼저 수행한다.

## 진단 원칙

증상이 여러 개 보일 때 "아마 이것 때문일 것"으로 여러 곳을 동시에 고치지 마라.

1. 각 증상을 **실제로 재현**한다.
2. 재현된 것만 **원인을 코드에서 특정**한다.
3. **최소 범위로 수정**한다(수정 파일 수를 보고한다).
4. 각 수정이 어떤 증상을 없앴는지 1:1로 검증한다.
5. 재현하지 못한 증상은 추측으로 고치지 말고, 재현에 필요한 조건을 사용자에게 묻는다.
