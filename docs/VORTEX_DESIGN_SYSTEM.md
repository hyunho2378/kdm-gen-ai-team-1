# VORTEX presentation-v2 디자인 시스템 및 인수인계

이 문서 하나만 읽으면 다른 창에서도 같은 기준으로 이어 작업한다. 발표용 웹사이트(presentation-v2)의 브랜드, 색, 섹션 구조, 문구, 인터랙션, 이미지 매핑, 바꿀 것, 작업 규율을 전부 담는다. 값이 충돌하면 이 문서가 기준이다.

---

## 0. 정체

- 제품명 VORTEX. 펜싱 검이 그리는 곡선의 궤적과 경기의 긴장감이 소용돌이처럼 몰입으로 이어지는 순간을 담은 이름.
- 한 줄. 거리와 타이밍을 몸으로 익히는 몰입형 펜싱 XR.
- 소속 2026 KDM+ AI Workshop 강원 지부. 팀 김다영, 주현호, 윤소희.
- 대상 폴더 presentation-v2. 기존 presentation은 손대지 않는다.
- 철학 세 가지. 텍스트는 명사 라벨 위주로 절제. 흉내 금지, 오픈소스 실제 설치. 섹션 하나씩 완성하고 실제 픽셀로 확인 후 다음.

---

## 1. 기술 스택과 조작 셸

- React 18 + Vite + JSX. TypeScript와 Next 금지.
- three.js + postprocessing(arena와 동일 버전, dedupe). GSAP + Lenis. OGL(표지 커서 궤적). lucide-react(아이콘).
- 색과 값은 presentation-v2/src/tokens.js 한 파일에서만 수정. shared/tokens.js는 이 작업에서 건드리지 않는다(앱 간 색 통일은 별개 과제).
- 문구는 presentation-v2/src/copy.js 상수로만. 컴포넌트 하드코딩 금지.
- 배포 Vercel.

### 조작 셸 (완성, 로직 자체는 안 건드린다)
- GSAP Observer + Lenis. 방향키, 스페이스, 휠 = 다음 섹션 이동. 1초 이징, 이동 중 입력 잠금, 우하단 진행 표시.
- 일부 섹션은 서브 진행 위임 구조를 쓴다. 섹션이 자기 핸들러를 등록하고, 머무는 동안 방향키가 내부 상태를 소비하다가 경계에서만 다음 섹션으로 이탈한다. 등록은 registerHandler, registerEnter 패턴. S2Why가 기준 구현이다.
- 중요 리팩터. 위임을 인덱스 하드코딩(currentRef===1 같은 숫자 비교)에서 섹션 id 기준으로 바꾼다. 섹션을 앞에 삽입할 때마다 인덱스가 밀려 위임이 깨지므로, id 기준이어야 삽입에 안전하다.

## 2. 디자인 시스템

### 2.1 색 (Color System 확정값)
- Primary 배경 black `#101010` (RGB 16,16,16). 순수 `#000000` 금지.
- 전경 텍스트 white `#FDFDFD`. 순수 `#FFFFFF` 금지. 흰 계열은 전부 이 값에서 파생.
- Branding Red `#E60D15` (RGB 230,13,21). 명중, 강조, CTA, 아이브로우 원, 유효 구간, TO-BE에만 절제해서. 화면 전체를 레드로 칠하지 않는다.
- Red Deep `#80070C` (그라디언트 중간 스톱).
- Red Glow `rgba(230, 13, 21, 0.45)`.
- Brand Gradient. `linear-gradient(105deg, #FDFDFD 0%, #E60D15 42%, #80070C 72%, #101010 100%)`. 스톱 순서 FDFDFD, E60D15, 80070C, 101010.
- 궤적 색 규칙(참고). 내 검은 실버 시안, 상대는 레드. 단 presentation-v2 로컬 토큰 기준이며 arena와의 색 통일은 별개 과제로 남아 있다.

### 2.2 폰트
- 본문 Pretendard 단일.
- 제목(디스플레이) 폰트는 미정. tokens에 displayFamily 키로 분리한다. 표지 워드마크, 컨셉명, 네이밍 워드마크가 이 키를 참조한다. 나중에 이 키만 바꿔 제목 폰트를 교체.

### 2.3 텍스트 규칙 (전역 강제)
- 명사형 종결 우선. 능동태.
- 금지 문자. 이모지, em dash `—`, 가운데점 `·`(U+00B7 및 유사 미들닷), 박스 라인 `─`(U+2500).
- 나열은 쉼표로. 예 "거리, 자세, 타이밍".
- 한글 분해는 word 단위만. char 단위 금지.
- copy.js와 컴포넌트에 위 금지 문자가 남지 않도록 grep으로 확인.

### 2.4 아이브로우 (전역 공용 컴포넌트)
- 모든 섹션의 아이브로우 라벨을 하나의 Eyebrow 컴포넌트로 통일한다.
- 라벨 왼쪽에 작은 원 하나. 채움 레드 `#E60D15`, 지름 6에서 8px, 텍스트 baseline 정렬.
- 라벨 weight 600 세미볼드로 전부 통일.
- 영문 위 국문 아래 스택 라벨을 지원. 단일 라벨도 지원.
- 개별 하드코딩 아이브로우는 제거하고 전 섹션이 이 컴포넌트를 쓴다.

### 2.5 모티프
- 검끝이 그리는 곡선 한 줄. 표지 커서 궤적, 컨셉 구분선, 로딩과 커서까지 하나의 선 문법으로 통일한다. 여러 가닥에 부드럽고 밝은 선이 아니라 가늘고 선명한 한 줄.

## 3. 섹션 구조 (최종 순서와 스펙)

순서. 표지, 배경, 인사이트, 문제, 대상, 디자인키워드, 네이밍, 컬러, 컨셉, 인터랙션, 유파, AI 워크플로우, 산출물, 끝.

각 섹션의 원본 레이아웃은 팀이 만든 SVG다. SVG는 텍스트가 아웃라인 패스라 글자를 못 읽으니, 레이아웃은 SVG를 PNG로 렌더해 눈으로 맞추고 문구는 이 문서를 원본으로 쓴다. SVG를 그대로 img로 박지 말고 React로 재구성한다.

### 3.1 표지 COVER
- 이미지 cover/fencer.png. 정사각 비율, 인물 중앙, 상단 빈 블랙. 사진 자체가 순수 블랙 배경이라 섹션과 이음매 없이 붙는다.
- 상단 빈 공간에 텍스트. 좌상단 "Team 1  김다영 주현호 윤소희", 우상단 "2026 KDM+ AI Workshop", 중앙 상단 메탈릭 워드마크 VORTEX(실버 볼륨 + 옅은 레드 글로우, displayFamily), 그 아래 서브카피 "거리와 타이밍을 몸으로 익히는 몰입형 펜싱 XR".
- 함정. 브랜드 그라디언트를 워드마크 글자에 직접 클립하지 마라. 마지막 스톱 #101010이 배경에 묻힌다. steelText로 클립하고 그라디언트는 아래 검끝 선으로 옮긴다. 픽셀로 검증된 함정이다.
- OGL Polyline 커서 궤적. 가늘고 선명한 레드 한 줄이 커서를 즉각 따라오고, 입력 없을 때는 중앙을 향한 완만한 나선을 스스로 그린다. 캔버스는 사진 위, 텍스트 아래. pointer-events none, 가산 블렌딩. 상세는 6절 라이브러리 항목.
- 초광폭에서 정사각 사진 좌우 여백은 인물 뒤 저알파 레드 radial 글로우로 눌러 준다.
- 진입 시 사진 opacity 0에서 1, 워드마크 지연 페이드업.

### 3.2 배경 PROLOGUE
- 아이브로우 PROLOGUE.
- 본문 한 문단. "펜싱은 빠른 공격보다 상대와의 거리, 타이밍, 움직임을 읽는 감각이 중요한 1:1 대결 스포츠다. 하지만 높은 진입장벽으로 많은 사람들에게는 '관람하는 스포츠'에 머물러 있다."
- 강조구 3개는 선명하게(FDFDFD 볼드 또는 레드 포인트), 나머지는 dim. 강조구: "상대와의 거리, 타이밍, 움직임", "1:1 대결 스포츠", "'관람하는 스포츠'".
- 이미지 없음. 진입 시 줄 단위 페이드업.

### 3.3 인사이트 PAIN POINT / INSIGHT
- 아이브로우 두 개. 상단 PAIN POINT, 하단 INSIGHT. 둘 다 레드.
- 상단 글래스 카드 3열(다크 글래스 테두리). 페인.
  - Functional (기능적). "거리감을 익히기 어렵고 자세 교정이 어려움". (원본 SVG 오타 Fuctional을 Functional로 교정)
  - Economic (경제적). "레슨비와 장비가 비싸고 연습장이 부족".
  - Social (사회적). "진입 장벽이 높고 같이 할 사람이 없음".
- 각 카드 아래로 점선 세로 화살표가 하단 카드로 내려간다.
- 하단 레드 카드 3열(레드 저알파 채움). 인사이트.
  - "피드백 받을 수 있는 시스템이 필요".
  - "일상에서 지속적으로 즐길 수 있는 환경이 필요".
  - "부담 없이 시작하고, 대결하며 성장할 수 있는 경험이 필요".
- 열 정렬. 기능에서 피드백, 경제에서 환경, 사회에서 경험으로 세로가 정확히 맞는다.
- 배경 흐린 펜싱 사진 1장(임시 시안). 진입 시 상단 카드 좌에서 우 stagger 후 화살표, 이어 하단 카드.

### 3.4 문제 WHY (AS-IS / TO-BE)
- 아이브로우 WHY 문제.
- 서브 진행 2단계.
  - 단계 0. asis.png 풀블리드, 그레이스케일. 하단 중앙 배지 AS-IS와 캡션 2줄.
  - 방향키 아래 단계 1. 사진이 transform으로 좌측 절반으로 축소 이동, 우측 절반에 tobe.png가 opacity와 밝기 상승으로 등장. TO-BE 배지는 레드 채움. 두 사진 사이 세로 경계에 얇은 그라디언트 라인.
- 헤드라인 2줄. "공간의 제약을 넘어, 일상의 공간이 현장이 되는 순간".
- width 애니메이션 금지, transform만. brightness 트랜지션은 이 사진 한 곳만 예외 허용.

### 3.5 대상 TARGET
- 아이브로우 스택 Target 대상.
- 헤드라인 "누구나 쉽게, 가장 가까운 취미 경험으로 전환하는 XR 경험".
- 원 3개. 채움 없음, 테두리만. 글래스모피즘 림. 배경 #101010이 그대로 비친다.
  - 글래스 테두리 구현. 배경 그라디언트 + mask로 1에서 1.5px 링만 남기는 방식. 예 `background: linear-gradient(160deg, rgba(253,253,253,0.5), rgba(253,253,253,0.06) 55%, rgba(253,253,253,0.18))`에 mask로 중심을 뚫는다. 위쪽 밝고 아래쪽 어두운 유리 림.
  - backdrop-filter는 배경이 단색이라 효과 없으니 쓰지 않는다.
  - 번호 01 02 03은 레드 #E60D15.
  - 본문 3개(강조 볼드 위치 유지). "펜싱을 가장 가까운 **취미로 만나고 싶은 사람들**", "해보고 싶었지만, **시작하기는 어려웠던 사람들**", "일상에 새로운 긴장과 **몰입을 원하는 사람들**".
- 그라데이션 채움 원은 폐기. 반드시 테두리만.

### 3.6 디자인키워드 (컨셉설명, Design Keyword)
- 아이브로우 스택 Design Keyword 디자인 키워드.
- 헤드라인 "빠르게 움직이고, 정확하게 판단하며, 끝까지 몰입한다."
- 본문 "본 제품은 펜싱의 핵심 경험을 XR 기술로 확장하여 실시간 피드백과 직관적인 인터페이스를 통해 더욱 효과적인 트레이닝 환경을 제공한다. 이를 위해 Dynamic, Precision, Immersion의 세가지 디자인 키워드를 바탕으로 형태와 사용자 경험을 전개한다."
- 카드 3장. 사진 위 중앙 원형 글래스 라벨(채움 없는 유리 테두리, 뒤 사진이 비침, 원 내부 backdrop-filter blur 2에서 4px 허용).

  - Precision 정확한. keyword/precision.png. "거리, 자세, 타이밍을 정밀하게 분석하는 XR 글라스".
  - Immersion 몰입하는. keyword/immersion.png. "현실과 디지털이 자연스럽게 결합된 몰입형 훈련 경험".
- 인터랙션. 5절의 포커스 서브 진행을 쓴다(정적 동시 표시 아님).

### 3.9 컨셉 CONCEPT (VORTEX 비주얼)

## 4. 서브 진행 인터랙션 규약

서브 진행 섹션은 셸의 registerHandler, registerEnter로 방향키를 내부에서 소비하고 경계에서만 이탈한다. transform, opacity, filter blur만 쓴다. 이징 tokens.motion. 이동 중 입력 잠금은 셸이 처리.

### 4.1 인터랙션 EXPERIENCE (서브 진행 아님)
4카드를 한 화면에 가로로 동시 표시. 진입 active 시 좌에서 우로 하나씩 밀려 들어오는 stagger(translateX + opacity, stagger 0.12에서 0.16s). 왕복 진입 시 재생되게 active 변화에 useEffect. 들어온 뒤 정지.

### 4.2 디자인키워드 포커스 (제자리 확대)
- 방향키로 3카드를 하나씩 포커스. 발표자가 리듬을 잡는다.
- 포커스 카드는 제자리에서 scale 1.06에서 1.1 확대 + 부양감(그림자, 글로우). 좌우 위치 이동 금지.
- 나머지 2장은 scale 0.94 축소 + blur 4에서 6px + brightness 0.6.
- 진입 방향으로 시작 인덱스 결정(위에서 아래면 1번, 아래에서 위면 3번 포커스). 경계에서만 섹션 이탈. 전환 0.5에서 0.6s. 역방향 대칭.

### 4.3 유파 포커스 (전진 + 좌측 + 상세)
- 상태 0 인트로. 카드 3장 가로 일렬.
- 상태 1. 카드1 앞으로 확대 + 좌측 이동, 나머지 blur + 어두워짐, 우측에 상세(스타일 2줄 + 인용 + 상세 미디어 슬롯). 상세 미디어는 아직 없어 다크 플레이스홀더.
- 상태 2. 카드1 느리게 원위치 복귀.
- 상태 3. 카드2 전진 + 좌측 + 확대, 상세.
- 상태 4. 카드2 복귀.
- 상태 5. 카드3 전진, 상세. 이후 아래로 섹션 이탈. 위는 역재생.
- dim, blur, z 정렬, 락 기반 한 칸 스텝은 6절 StackCarousel 메커니즘 이식.

주의. 디자인키워드는 제자리 확대, 유파는 좌측 이동 + 상세다. 두 모션이 너무 달라 통일감이 깨지는지는 1차 구현 후 판단.

## 8. 작업 규율

1. 실제 픽셀로 검증. canvas 주입 0에러가 아니라 dev 서버를 띄우고 각 섹션과 각 서브 단계를 방향키로 순회하며 스크린샷으로 육안 확인한다. 이미지 부재 상태에서도 안 죽는지 확인.
2. SVG 사용. 레이아웃은 SVG를 PNG로 렌더해 대조, 문구는 이 문서를 원본으로. SVG를 img로 박지 말고 React 재구성.
3. 색은 tokens.js 한 파일, 문구는 copy.js 한 파일. 하드코딩 금지.
4. 애니메이션은 transform과 opacity 위주. blur는 포커스 연출에 한정. reduced-motion 대응.
5. 영역 소유. 같은 시간대에 두 세션이 App.jsx를 동시에 만지지 않는다. 인터랙션 개편과 유파 개편처럼 App.jsx를 건드리는 작업은 하나 끝내 커밋 후 다음.
6. 커밋 메시지 `[presentation] 한 일`. 세션 끝에 PROGRESS.md에 완료, 진행중, 미해결(이미지 교체 필수 포함) 기록.
7. 셸 로직(GSAP Observer, Lenis, 이동 이징)은 건드리지 않는다. 섹션 내부만 작업.
