## A. 미디어 프레임 시퀀스 (`components/MediaSequence.jsx`)

**GLB 아님. 이미지 시퀀스**(ffmpeg로 쪼갠 프레임)를 스크롤/트리거에 매핑한다.

### A.1 ffmpeg 프레임 파이프라인 (영상 → webp 프레임)

영상이 확보되면 아래로 프레임을 쪼갠다. **fps와 총 프레임 수를 변수로 둔다.**

```bash
# 변수
SRC=input.mp4          # 원본 영상
FPS=24                 # 초당 프레임 수 (시퀀스 재생 fps와 일치시킨다)
OUT=public/frames/<name>   # 출력 폴더

mkdir -p "$OUT"
# webp로 가볍게. frame-000.webp ~ 로 0패딩(정렬/프리로드 URL 생성 편의).
ffmpeg -i "$SRC" -vf "fps=$FPS,scale=1024:-1:flags=lanczos" -q:v 70 "$OUT/frame-%03d.webp"

# 총 프레임 수 확인(컴포넌트에 N으로 넘긴다)
ls "$OUT" | wc -l
```

- **webp**로 가볍게, `scale`로 폭 고정(원본 그대로면 프리로드가 무겁다).
- 프레임 URL 배열을 `frames` prop으로 넘긴다: `Array.from({length:N}, (_,i)=>` `` `/frames/<name>/frame-${String(i).padStart(3,'0')}.webp` `` `)`.
- `fps`는 enter 모드의 재생 속도(`dur = N/fps`)에 쓴다.

### A.2 두 재생 방식 (한 컴포넌트로 일반화)

| mode | 동작 | 자리 |
|---|---|---|
| `scroll` | **스크롤 진행 0~1을 프레임 0~N에 매핑.** 바깥이 스크롤 길이(200dvh), 안쪽 `sticky`로 붙는다. blur→sharp 수렴 함께 | 딥다이브형 미디어 |
| `enter` | **진입(IntersectionObserver) 1회 재생.** 흐림→선명으로 한 번 돌고 **마지막 프레임 고정** | 히어로/대표 미디어 |

- **회전 또는 흐림에서 선명 수렴 both 지원.** 프레임 자체가 회전이면 프레임 스왑이 회전을, blur 필터가 선명 수렴을 낸다.
- **프리로드**: 마운트 시 모든 프레임을 `new Image()`로 디코드해 스왑 끊김을 없앤다.
- **플레이스홀더**: `placeholderFrames(n)`이 SVG data-URI 프레임 n장(프레임 번호 + 진행)을 만들어 에셋 없이 로직을 테스트한다.
  실측: 대표 미디어 enter 모드가 `frame 000`(blur)에서 `frame 023`(sharp)까지 1회 재생 후 고정됨을 확인.

### A.3 pin/워프 충돌 방지

**`sticky`다. GSAP pin(`fixed`)이 아니다.** transform이 걸린 조상(R3 ScrollWarp)에서 `fixed`는 뷰포트 기준을
잃는다(PITFALLS 실측: pin 섹션이 top 0 → -1836으로 날아감). scroll 모드는 sticky 무대(`top: var(--pnav-h)`)라 이 함정을 안 밟는다.

### A.4 reduced-motion

`prefers-reduced-motion: reduce`면 연출 없이 **마지막(선명) 프레임 하나**만 세운다.

## B. 호버 자동 재생 (`components/HoverMedia.jsx`)

지정 슬롯(제품 뷰, 미디어 카드)에 마우스가 오면 그 위 영상이 재생, 떼면 정지+첫 프레임 복귀.

- **`<video muted playsInline loop>`.** 자동재생 정책상 `muted` 필수, `playsInline`이라 모바일에서 전체화면 안 뜬다.
  호버 진입 `play()`, 이탈 `pause()` + `currentTime = 0`. 클릭 유도 없이 마우스만으로 미리보기.
- **커스텀 커서(R1 `Cursor.jsx`)와 연동.** 슬롯에 `data-cursor`를 달면 Cursor의 위임 셀렉터(HOT)에 자동으로 걸려
  호버 시 커서가 커진다. Cursor가 document 위임이라 나중에 생긴 요소도 별도 배선 없이 걸린다(실측: 뷰 슬롯 3개 `data-cursor` 확인).
- **영상 없을 때(slot)**: `src`가 없으면 영상 태그 대신 대기 표면(`이미지/영상 첨부 예정`)만 둔다. 호버/커서 로직은 그대로 살아 있다.
- **프레임 시퀀스 호버 재생**이 필요하면 A의 MediaSequence를 호버 진행에 연결한다(현재는 video 우선).
- reduced-motion·터치(`hover: none`)에서는 자동재생을 걸지 않는다(호버 개념이 없다).

**배선**: 제품 페이지 뷰 슬롯(Side/Front/Top)이 HoverMedia 플레이스홀더다. 영상이 오면 `src`만 채운다.

## C. 파도 웨이브 (`components/WaveReveal.jsx`)

**용도 판단(보고).** 두 용도 중 **요소 등장 웨이브**를 택했다.

| 용도 | 판단 |
|---|---|
| 배경 앰비언트 물결 왜곡(WebGL 셰이더) | **보류.** 상시 렌더라 저사양에서 프레임을 먹고(성능 부담), 라이트 팔레트에 은은해야 해 존재감도 약하다. |
| **요소 등장 웨이브(채택)** | 텍스트/카드가 파도처럼 순차로 물결치며 등장. 기존 `data-beat` 리빌 시스템의 **stagger 확장**이라 가볍다. |

- 직속 자식이 웨이브 단위. 각 자식이 `y + opacity`에서 **stagger(sine 이징)**로 물결친다. transform/opacity만.
- ScrollTrigger `once: true`(되감아도 안 사라진다). ProductLayout의 `data-beat`와 겹치지 않게 자식엔 data-beat를 안 단다.
- reduced-motion에서 **비활성**(정적으로 그대로 보인다).
- **배선**: 제품 뷰 슬롯 3개(Side/Front/Top)가 WaveReveal로 물결치며 등장.

앰비언트 물결이 꼭 필요하면 히어로 배경에 가벼운 CSS 기반(느린 background-position/mask 왜곡)으로 별도 추가한다(성능 우선).

### D.1 히어로 (블랙 표지 구도, `components/HeroCover.jsx`)

발표 표지 구도를 그대로 세운다. **마스크(좌)와 컨트롤러(우)가 중앙 로고를 향한다.**

```
1. 인물이 중앙에서 좌측으로 이동하며 등장        xPercent 42 -> 0
2. 컨트롤러가 우측 하단에서 중앙으로 이동하며 등장  xPercent -34, yPercent 30 -> 0
3. 로고가 중앙에 안착                           scale 0.86 -> 1
```

`transform`과 `opacity`만 건드린다(MOTION 11절). 레이아웃을 안 읽으므로 리플로가 없다.

**이 구간만 블랙이다.** 페이지 전체는 라이트 그라디언트인데(`html`이 진다) 이 섹션이 그 위를 덮는다. **아래로 내려가면 라이트로 열리는 대비가 이 히어로의 절반이다.** 섹션 바닥에 블랙에서 투명으로 가는 띠를 두어 경계가 칼로 자른 선으로 안 보이게 한다.

**리본 궤적(`HeroTrail`)을 걷었다.** 근거 둘.
1. 표지 구도가 주인공인데 움직이는 것이 넷이 되면 시선이 갈린다.
2. 그 리본은 **라이트 배경용 잉크(#101010)로 튜닝**돼 있어(BV2-2에서 크롬 그라디언트를 걷고 평면 잉크로 내린 값) 블랙 위에서 안 보인다.

덤으로 WebGL 컨텍스트 하나가 줄어 아래 영상 둘과 같이 돌 때 유리하다. `HeroWordmark`도 소비자가 사라져 함께 걷었다(로고 SVG가 그 자리를 진다).

**아이브로우만 공용 컴포넌트를 안 쓴다.** 그것은 라이트 팔레트라 영문이 네이비(#263E5F), 국문이 잉크 60퍼센트인데 **블랙 위에서 둘 다 안 보인다**(실측 1.9:1과 1.1:1). 이 섹션에서만 흰 계열로 세운다(고친 뒤 20.65:1과 7.26:1).

**모션 감소에서는 셋이 최종 자리에 그대로 선다.** 등장만 생략하고 구도는 같다.

### D.4 자동 재생 정책 (`components/AutoVideo.jsx`)

iOS와 안드로이드 모두 **`muted` + `playsInline`**이면 사용자 제스처 없이 재생을 허용한다. 셋 중 하나라도 빠지면 `play()`가 거부된다.

**거부를 다 같게 보면 안 된다(실측으로 잡았다).** 빠르게 스크롤해 지나가면 아직 안 풀린 `play()`를 관찰자의 `pause()`가 끊고 그것이 **`AbortError`**로 온다. 정상 동작인데 그때 컨트롤을 켜면 **한 번 훑고 지나간 것만으로 영상이 영영 컨트롤 달린 채로 남는다.** 자동 재생이 막힌 것은 **`NotAllowedError` 하나**이고 그때만 사람이 누를 길을 연다.

**모션 감소에서는 재생하지 않는다.** 자동으로 도는 영상은 그 설정이 막으려는 바로 그것이다. 첫 프레임에서 멈춘 채로 서고 컨트롤이 뜬다.

**둘째 카드는 `con-360.mp4`다.** 작업 중에 도착한 파일이고 `mask-360`과 같은 규격(1920x1920, 5.08초)이라 같은 비율과 같은 속도를 준다. 셋째(`Vortex Duel`)만 대기다.

### E.2.1 재생권은 한 장에게만 (성능. 실측으로 잡았다)

**1440에서 이 레일은 카드 두 장을 통째로 보여 준다**(520 + 24 + 520 = 1064 < 1425). 그런데 소스가 1920x1920이라 **둘이 동시에 디코드되면 스크롤 중 프레임이 무너진다.**

| 동시 재생 | p50 | p95 |
|---|---|---|
| 0장 | 59.9 | 57.5 |
| 1장 | **59.9** | 57.5 |
| **2장** | **15** | 14.8 |
| 3장 | 29.9 | 14.9 |

**절벽이 정확히 두 장째다.** 디코더 자체는 멀쩡하다(5초 동안 `getVideoPlaybackQuality()`의 `droppedVideoFrames` **0**, `currentTime`도 정확히 rate만큼 나아간다). 무너지는 것은 프레임 예산이다.

**가만히 둔 상태의 rAF는 못 믿는다.** 재생 0장에서도 15로 읽혔다(헤드리스가 damage 없이 BeginFrame을 늦춘다). 그래서 위 표는 **매 프레임 스크롤로 damage를 만든 상태**의 값이고, 판단 근거는 rAF가 아니라 디코더 지표를 함께 봤다.

고친 방법 둘.

1. **레일은 제일 많이 보이는 한 장만 돌린다.** 레일 자신을 `root`로 삼는 관찰자가 카드의 `intersectionRatio`를 재고 최대인 것에게만 재생권을 준다. 스냅 캐러셀이라 어차피 한 장이 자리를 잡고, 넘기면 재생권이 그 자리로 옮겨 간다(실측: 다음 화살표 한 번에 `mask-360` 정지 / `con-360` 재생).
2. **AutoVideo의 세로 여백을 15퍼센트에서 0으로 좁히고 문턱을 0.01에서 0.25로 올렸다.** 넉넉히 잡으면 캐러셀을 보는 동안 한참 아래 수렴 영상까지 같이 돌았다. 화면에 4분의 1은 들어와야 시작이고 그때는 이미 눈에 보이는 자리라 늦지 않다.

고친 뒤 **네 자리(캐러셀, 넘긴 뒤, 수렴, 닫는 영상) 전부 동시 재생 1장, p50 59.9 / p95 56.8~57.8.**

**스냅 버그를 하나 잡았다.** `padding-inline`이 36.5인데 첫 카드의 x가 **0**이었다(실측). `scroll-snap-align: start`가 맞추는 기준은 패딩 박스이고 `mandatory` 스냅이라 브라우저가 로드 직후 `scrollLeft`를 패딩만큼 밀어 정렬해 버린다. `scroll-padding-inline: var(--page-gutter)`로 스냅 기준선을 들여 고쳤다(고친 뒤 x 37).

### E.3 수렴 스크롤 섹션 (`components/ScrubSection.jsx`)

**스크롤에 거는 것은 영상의 `currentTime`이 아니라 섹션 진행이다.** 스크럽으로 프레임을 직접 찾으면 매 스크롤마다 mp4 seek이 걸리고 8MB짜리 소스는 키프레임 사이를 되감느라 프레임을 떨어뜨린다. 영상은 관찰자가 제 속도로 돌리고 스크롤은 정보와 관문의 진행만 쥔다.

| | 값 |
|---|---|
| 스크롤 길이 | 280dvh(좁은 화면 220dvh). 안쪽이 `sticky top: var(--pnav-h)` |
| 영상 | `min(56vw, 760px)`. 1440에서 **760x425**, 좌우 여백이 **각 333** |
| 정보 | 넷을 좌우로 갈라 세운다(짝수 왼쪽, 홀수 오른쪽). 진행 1/6 2/6 3/6 4/6에서 하나씩 |
| 관문 | 진행 **0.82**에서 `제품 상세보기`가 열리고 `/mask`로 간다. 안 열렸을 때는 `tabIndex -1` + `aria-hidden`이라 포커스도 안 잡힌다 |
| 무대 색 | **`#081C29`** |

**무대 색은 짐작이 아니라 실측이다.** 영상 좌우 가장자리 세로 띠를 캔버스로 세 시각 평균해 `rgb(8,28,41)`을 얻었다. 라이트 판 위에 어두운 사각형이 얹힌 것으로 안 보이고 영상이 무대에 녹는다.

**위 여백을 줄였다.** 캐러셀 섹션의 아래 패딩만 `--section-gap`의 절반으로 내려 두 판 사이 간격이 **0**이 된다(실측). 어두운 판이 페이지에서 떨어져 나온 조각으로 안 읽힌다.

**한 번 선 정보는 안 사라진다.** 되감을 때 글자가 깜빡이며 없어지는 것이 이 문법의 실패 모드다(ProductLayout의 `once`와 같은 이유).

### E.4 마스크 면 프레임 시퀀스

**`ffmpeg`가 이 기계에 없다**(`which ffmpeg` 실패). A.1의 파이프라인을 그대로 못 돌리므로 **같은 일을 크롬으로 했다.** `video`를 시각마다 seek해 canvas에 그리고 `toDataURL('image/webp')`로 뽑는다. 디코더는 크롬 자신의 것이고 출력 규약(`frame-000.webp`, 0패딩, 폭 고정)은 A.1과 같다.

```
출력   brand/public/frames/mask-360/frame-000.webp ~ frame-029.webp
치수   760x760, 30장, 합계 734KB
재생   MediaSequence mode='enter', fps 16 -> 1.9초 동안 blur 10px -> 0
```

`fps`를 24가 아니라 **16**으로 잡았다. 30장을 24fps로 돌리면 1.25초라 한 바퀴가 스칠 만큼 빠르다.

### E.5 3D 뷰어를 걷었다

딥다이브 고정 미디어가 `three.js` 뷰어였는데 **띄우던 것은 실제 제품이 아니라 플레이스홀더 프리미티브였다.** 실제 렌더가 확보되면서 짐작으로 세운 도형을 돌릴 이유가 없다.

- `components/ProductViewer.jsx` 삭제. 조작 안내(`드래그해 돌린다`)와 WebGL 실패 안내와 `TODO_PRODUCT_MODEL`도 읽는 곳이 없어져 함께 걷었다.
- `npm uninstall three`. **brand에 three를 쓰는 파일이 하나도 안 남았다**(히어로 리본은 D회차에 이미 사라졌다).
- `vite.config.js`의 `resolve: { dedupe: ['three'] }`도 걷었다. arena 파일을 직접 import하던 시절 Vercel `Rolldown failed to resolve import "three"`를 막던 장치인데 대상이 없다.
- 걷은 뒤 brand 번들 **360KB(gzip 125KB)**.

### E.6 렌더 배치

| 자리 | 마스크 | 컨트롤러 |
|---|---|---|
| 대표 미디어 | **프레임 시퀀스**(520x520) | `con-front` 한 장 |
| 딥다이브 고정 | `mask-front` | `con-side` |
| Side View | `mask-side` | `con-side` |
| Front View | `mask-front` | `con-front` |
| Top View | **대기 표면**(렌더 없음) | `con-top` |

**렌더가 슬롯보다 적어 겹치는 자리가 하나씩 있다**(마스크는 `mask-front`, 컨트롤러는 `con-side`가 딥다이브와 뷰 슬롯 둘 다에 선다). 큰 무대와 작은 슬롯이고 그 사이에 딥다이브 한 편이 통째로 들어가 있어 나란히 읽히지는 않는다. 뷰 렌더가 더 오면 겹침이 풀린다.

**마스크 탑 뷰 렌더는 없다.** 지어내지 않고 대기 표면으로 남긴다.

**뷰 슬롯 비율을 4:3에서 1:1로 바꿨다.** 원본이 정사각이라 4:3에 넣으면 위아래가 잘린다.

### E.7 제품 렌더 무대 색

**렌더와 프레임이 전부 검은 스튜디오 바탕에서 찍혔다.** 라이트 카드(`--card-bg`) 위에 얹으면 그 검은 사각형이 판 위의 이물로 읽힌다. `.vx-prod-stage`가 소재와 같은 바탕을 깐다.

**`#000`인 이유도 실측이다.** 다섯 렌더와 프레임의 네 모서리를 찍어 보니 0~4였다(`mask-front` [2,2,2], `con-side` [1,1,1], `frame-000` [0,0,0]). `#050505` 같은 값을 깔면 이음매가 한 단 밝게 보인다.

**특정도 함정을 하나 밟았다.** `.vx-prod-stage`를 깔았는데 배경이 `rgba(16,16,16,0.035)`로 나왔다(실측). `.vx-seq`와 `.vx-hover-media`가 이 파일 아래쪽에서 자기 표면을 깔고 **한 클래스끼리는 뒤에 온 쪽이 이긴다.** 두 클래스를 겹쳐 잡아 되찾았다.

딥다이브 렌더는 별도 무대 요소 없이 이미지 자신이 슬롯을 다 진다. 와이드 슬롯이 1425x704(2.024:1)인데 렌더는 정사각이라 `object-fit: contain`으로 가운데 세우고 남는 좌우를 `background: #000`으로 채운다. 소재 바탕과 같은 값이라 이음매가 없다.

### E.8 닫는 영상 (man-mak) 배치 판단

**오버뷰의 마지막 미디어 자리, 원칙 바로 앞이다.** 근거 둘.

1. 캐러셀이 제품을 세우고 수렴 섹션이 판정을 말한 뒤 남는 것이 이 장면이다. 겨루기 **이후**라 순서상 마지막이 맞다.
2. 바로 뒤 원칙의 마지막 줄이 **"장비가 아니라 감각을 남긴다"**이다. 마스크를 내리는 장면 다음에 이 문장이 오면 둘이 붙어 한 문장으로 읽힌다(실측으로 순서 확인).

무대 색 **`#1E2F46`**도 같은 방법으로 잰 값이고(rgb(30,47,70)) 브랜드 네이비 `#263E5F`와 이웃한 자리라 페이지에 자연스럽게 앉는다.
