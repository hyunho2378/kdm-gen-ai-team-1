## 확정된 조작 규칙 (가드 재설계 완료, 커밋됨)

실기에서 "폰 세로 = 가드"가 게임을 깨뜨린 것을 발견하고(쉬는 자세가 곧 가드라 judge의 `if(guarding) return PARRY`가 상시 걸려 AI 득점 8→0, 사용자 20/20 승) 조작을 바꿨다. **현재 확정:**

```
폰 세로 (단자 아래, 화면 몸 쪽)   앙가르드 중립. 이산 이벤트 없음
폰을 좌우로 기울임 (아무 쪽이나)   가드. 세로 복귀에 풀림
폰을 앞으로 눕히며 지름           찌르기 (가속 감지 A방식)
```

핵심 불변식: **세로 중립에서 어떤 이산 이벤트도 발화하지 않는다.** 쉬면 가드도 찌르기도 아니어야 AI가 위협이 된다.

### 축 분해 수학 (shared/pose.js 한 곳, controller 실기와 arena posetest가 공유)
- 오일러각 안 씀(순서 의존, 짐벌락에서 축 엉킴). **칼끝 벡터 구면 좌표**: roll = asin(x), pitch = atan2(-z, y). 순수 좌우는 roll만, 순수 앞뒤는 pitch만 움직인다.
- 기준 쿼터니언(캘리브레이션 시 폰 세로, 단자 아래)의 켤레를 곱한 상대 회전에서 pitch/roll 분해.
- **GRIP_TO_BLADE = x축 +90도** 고정 보정. 폰 세로축(단자→상단)이 칼날 방향인데, 회전을 그대로 얹으면 칼날이 기기 -Z(화면 뒤)를 따라가 90도 어긋난다. 이 보정으로 세로→검 수직, 앞으로 눕힘→검 전방이 맞는다.
- 가드 문턱: roll 기준 ON 25도 / OFF 15도(히스테리시스). 우세 축 여유 10도. pitch(앞뒤)가 커도 roll 작으면 가드 아님(찌르기와 독립).

### 찌르기(THRUST) 가속 임계 — 중요한 함정 해결됨
- **임계 18이 EMA 뒤의 값이라 실제 원 피크 37 m/s²(3.8G)를 요구**했다. EMA(0.2, 시정수 83ms)가 120ms 펄스를 원 피크의 56%로 깎기 때문. 이게 사용자 체력 소모의 근본 원인이었다.
- **8로 내렸다**(원 피크 17 = 1.73G, 손목 스냅 범위). 크기를 내려도 오탐 안 늘었다 — 걷기/고쳐잡기를 자르는 건 크기가 아니라 수평비와 최소지속이다(오탐 7종 임계 6/8/10/12 전부 0건). 크기 관문은 오탐을 안 막고 체력만 쓰고 있었다.

### 캘리브레이션 버그 수정됨
- setBaseline이 상대 자세를 그 자리에서 재계산 안 하면 캘리브레이션 직후 한 틱이 보정 전 각도로 남아 경기 시작 순간 엉뚱한 guard on/off가 판정에 샜다. 닫음.

### 디버그 도구 (몸 안 쓰고 검증)
- **?posetest=1** (arena): pitch/roll 수동 입력으로 검 자세와 판정 상태(중립/가드/찌르기) 미리보기. 폰 안 흔들고 매핑 확인.
- **?debug=1** (controller): roll/pitch + "수평 최대"(임계와 같은 단위, 2초 유지) 표시. 앉아서 손목으로 지르고 값이 임계 넘는지 눈으로 확인.
- **?cam=1** (arena): 웹캠 추적 상태, 머리 x, 안정도 값.

## AI 밸런스 실측 (가드 중립화 후)

판정 무변경, 가드 대본만 교체한 4유파×5시드 20경기:
- 상시 가드(예전): AI 0점, 나 20/20 승
- 자주 막음 26%: AI 8점
- 가끔 막음 11%: AI 30점
- 안 막음 0%: AI 47점, 나 16/20 승

세로 중립화로 AI가 다시 위협이 된다. 현실적 가드 점유 10~25%면 AI 8~30점. **단 사용자는 아직 폰 실기로 새 조작을 검증 못 함**("컨트롤러 이후를 안 해봄"). 조작이 실기로 되는지 먼저 확인해야 AI 난이도 조정의 진짜 기준이 선다.

## 실루엣 구조 (three/opponent.js — 화면의 상대는 이 경로다)

- **fighters.js는 2D 폴백(막대기 다리), 화면의 발광 실루엣은 three/opponent.js.** 미세조정 대상은 three 경로.
- **골격**: 관절 좌표(hip→knee→foot, shoulder→elbow→hand)로 그린다. 무릎 관절이 이미 있다. POSES에 5포즈(IDLE/ADVANCE/TELEGRAPH/LUNGE/HIT) 좌표 정의됨. 정규 좌표(x 0~1이 텍스처 폭, y 0~1이 높이), 텍스처 512×1024가 0.95m×1.9m라 **비등방**(정규 0.1이 x에서 51px, y에서 102px — 원형 머리는 x반지름이 y의 2배).
- **비주얼 C(실루엣 후처리) 완료**: 부위 테두리 제거하고 합집합 마스크로 관절을 잇고, 뒤쪽 팔다리는 크게 흐린 그늘(SEAM_BLUR 16)로 깊이, 가장자리 페더(FEATHER 3), 바깥 헤일로는 알파 확산(destination-over, 밝기 안 올림). **블러는 전부 로드 시 bake, 런타임 0.** 마스크 테두리 제거(블룸 문턱 닿던 원인).
- **블룸 천장 선형 0.42가 모든 밝기의 상한.** UNIFORM_DARKEN 0.30(sRGB 0.60), SHEEN_ALPHA 0.09, BLADE_RISE 0.42 전부 이 문턱 아래로 역산된 값. 올릴 때 반드시 재실측.
- **부위 두께**: 허벅지 78 / 종아리 52 / 팔 상완 46 / 전완 38 / 몸통 54.
- **검**: 텍스처에 안 그림. 3D 골동 레이피어가 손 앵커(HAND 좌표)에 붙어 겨냥(AIM)으로 회전. setFlare로 밝기만 올림(색은 steel.mid, red는 사건 전용). 찌를 때/예고 때 칼날 세워 가독성 확보.
- **풋워크(E4)**: SWAY_X 0.045 좌우, 호흡·큰숙임 압축(발바닥 축), 발레스트라 홉. 예고(TELEGRAPH)엔 시간을 얼려 "정지가 온다는 신호". 전부 렌더 전용 시드 난수, 판정 무관.
- **유파 기술(R4)**: TECH_SPEC에 베기 호(bow), 리치(reach), 딥(dip). 사브르계는 베기·플런지(발 교차 금지), 에페는 찌르기·플레슈. 전부 시각 계층, 판정 무관.

## 지금 진행 중 / 대기 프롬프트 (실행 순서)

작성해 둔 프롬프트들. 각각 독립이고 새 세션에 하나씩 넣는다.

1. **OPPONENT_POSE_REFINE.md** [렌더, 키보드로 검증 가능, 서명 유지]: 상대 다리 두께 균일(78/52→비슷하게), 오다리 완화(knee x 안쪽), 앙가르드 강화(무릎 굽힘·무게중심), 마스크 선명(GEAR_BLUR 낮춤). **한계: 빌보드라 항상 카메라 정면 향함 → "옆으로 선 펜싱 자세"는 구조상 불가, 무릎 굽힘·무게중심으로 "겨눔"까지만.** 좌표 바꾸면 HAND/AIM 검 손 위치 정합 확인 필수.
2. **INPUT_CAM_TUNING.md** [입력, 서명 유지]: 폰 기울기 "그때그때 다름" → **yaw 드리프트가 roll 오염**이 유력(Madgwick가 지자기 없이 yaw 드리프트, 근본 해결은 중력 벡터 앵커로 yaw 안 씀) + 캘리브레이션 재기준. 캠 앞뒤 인식 둔함 → 민감도 상향(단 focused만 판정, 아날로그 유입 금지).
3. **AI_DISTANCE_LOGIC.md** [게임플레이, **서명 갱신 1회**]: 내가 전진하면 상대가 후퇴해야 하는데 안 함 → 거리 밖 오류. AI 거리 관리 추가(기존 preferredD 확장, 중복 신설 금지). **핵심 불변식: AI 후퇴 속도 < 내 전진 속도(1.3m/s)** 아니면 영원히 못 잡음(0.6~0.9 유파차등). R3의 "d 동역학 보존" 주석 의도적 폐기 명시. 유파 차등(에페 잘 물러남, 세이버 압박), 경계로 몰면 라인몰기.

## 새 세션 시작 방법

1. 이 문서 + 필요 프롬프트(위 1~3 중 하나) 붙인다.
2. `git pull --rebase origin main` → 프로젝트 지침/PITFALLS 읽기 → 해당 프롬프트의 세션 시작 목록대로 실제 파일 읽기 → 현재 서명(1097/c820d0f2) 그린 확인 → 작업 → 검증 → 커밋/push.
