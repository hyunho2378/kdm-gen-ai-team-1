# DESIGN.md 간합 디자인 시스템 v2

블랙 위에 크롬과 레드. 간합의 시각 언어를 정의한다. presentation, brand, arena, controller 네 앱이 이 문서 하나를 공유한다.

---

## 0. 이 문서의 지위

토큰의 단일 원천은 `shared/tokens.js`다. 각 앱의 `src/tokens.js`는 재수출만 한다. 값 수정은 `shared/tokens.js`에서만 한다. 시각디자이너 확정안이 오면 그 파일만 교체하고 이 문서를 갱신한다. 하드코딩 금지.

스킬 충돌 시 우선순위는 프로젝트 지침, 다음 fullstack-product-setup, 다음 나머지 스킬.

v2 변경 요약: 네이비 배경 폐기, 오프블랙 전환. 탁한 중간 회색 전량 폐기. 크롬 스틸을 재질로 승격. 레드를 빛과 채움 둘로 분리해 채도 상향. 내 궤적 레드, AI 상대 궤적 블루로 소유 색 확정.

## 1. 세계관 규칙 셋 (모든 화면의 판단 기준)

1. **배경만 어둡다. 요소는 전부 밝다.** 무대는 블랙이고 검, 궤적, 타이포, HUD는 빛이다. 어두운 배경 위에 어두운 요소를 올리지 않는다. 화면이 탁하면 이 규칙을 어긴 것이다.
2. **무채색 필드에 유채색은 레드와 블루 둘뿐.** 배경과 재질은 전부 무채색(블랙, 크롬, 화이트)이다. 그래서 레드가 뜨는 순간 시선이 강제로 끌린다. 장식용 제3의 유채색을 추가하지 않는다.
3. **탁한 색 금지.** 애매한 중간 회색, 채도 낮은 색, 알파를 과하게 낮춘 흐릿한 색을 쓰지 않는다. 회색처럼 보이는 것은 전부 크롬 재질의 음영 스톱이거나 얼음빛 화이트의 알파다. 단독 회색 HEX 토큰을 만들지 않는다.

## 2. 색상

### 배경 (블랙)

| 토큰 | 값 | 용도 |
|---|---|---|
| bg.base | #0B0B0E | 기준 배경. 지각상 블랙, 쿨 톤 오프블랙 |
| bg.deep | #050506 | 그라디언트 하단, 비네트, arena 외곽 |
| bg.raised | #15151A | 카드, 패널, HUD 판넬 |

순수 #000은 쓰지 않는다. 깊이는 base에서 deep으로 떨어지는 수직 그라디언트와 방사 비네트로 만든다. 네이비 틴트는 폐기한다.

### 레드 (주인공)

레드는 빛일 때와 면일 때 값이 다르다. 이 분리가 쨍함과 가독성을 동시에 지킨다.

| 토큰 | 값 | 용도 | 대비 실측 |
|---|---|---|---|
| red.light | #FF2442 | 빛의 레드. 내 궤적, 다크 위 레드 텍스트, 글로우 코어, 명중 UI | bg.base 위 5.2:1, AA 통과 |
| red.fill | #D90429 | 면의 레드. CTA 버튼, 배지, 명중 플래시 채움 | 위에 흰 텍스트 5.3:1, AA 통과 |
| red.press | #A6031F | 버튼 press 상태 | 채움 전용 |
| red.glow | rgba(255,36,66,0.4) | 궤적 잔광, 글로우 외곽 | 장식층 |

기존 #B3122C는 블랙 위에서 2.2:1로 가라앉아 폐기한다. 어두운 배경 위 가는 선과 텍스트는 반드시 red.light, 넓은 채움은 red.fill을 쓴다.

### 블루 (상대)

| 토큰 | 값 | 용도 | 대비 실측 |
|---|---|---|---|
| blue.light | #35C8FF | AI 상대 궤적, 상대 소유 표시 | bg.base 위 9.8:1 |
| blue.glow | rgba(53,200,255,0.35) | 상대 궤적 잔광 | 장식층 |

블루는 상대의 색이다. 내 것에 쓰지 않는다. CTA와 브랜드 맥락에도 쓰지 않는다. 상대 식별이라는 단일 임무만 가진다.

### 크롬 스틸 (재질, 단색 아님)

레퍼런스의 금속 타이포와 사슬을 시스템으로 옮긴 것이다. 크롬은 색이 아니라 그라디언트 재질로 정의한다.

```
steel.hi      #FFFFFF                     하이라이트 스톱
steel.mid     #D8E2F0                     본체 스톱, 얼음빛
steel.shadow  #6E7B92                     음영 스톱. 그라디언트 내부 전용, 단독 사용 금지
steel.edge    rgba(255,255,255,0.9)       베벨 상단 림
```

CSS 구현: `linear-gradient(175deg, steel.hi 0%, steel.mid 45%, steel.shadow 78%, steel.mid 100%)` + `background-clip: text`. 디스플레이 타이포, 로고, 검신 렌더, 구분선 하이라이트에만 쓴다. **본문과 caption과 HUD 텍스트에는 절대 쓰지 않는다.** 작은 크기에서 그라디언트는 가독성을 죽인다.

steel.shadow를 단독 텍스트 색으로 쓰는 순간 "애매한 회색"이 부활한다. 금지.

### 텍스트 (얼음빛 화이트)

순수 흰색 대신 아주 옅게 차가운 화이트를 쓴다. 크롬과 같은 온도로 맞아 떨어진다.

| 토큰 | 값 | 용도 |
|---|---|---|
| text.primary | #F2F6FF | 제목, 본문, HUD 주 텍스트 |
| text.secondary | rgba(242,246,255,0.78) | 보조 설명 |
| text.dim | rgba(242,246,255,0.55) | caption, 비활성. 이 아래 밝기 금지 |
| line.default | rgba(242,246,255,0.14) | 헤어라인 |
| line.strong | rgba(242,246,255,0.32) | 강조 보더 |

text.dim보다 어두운 텍스트를 만들지 않는다. 0.55 알파가 bg.base 위에서 읽히는 하한선이다.

### 궤적과 명중

내 검 red.light, AI 상대 blue.light. 명중 순간 해당 세그먼트 코어를 #FFFFFF로 굵게 고정하고 잔광만 소유 색으로 남긴다. 블랙 무대 위에서 흰 섬광이 최종 강조가 되는 구조다. 색만으로 소유를 구분하지 않고 HUD에 텍스트 라벨을 병기한다.

### 검과 레드의 관계 (개정)

실플레이 크리틱에서 나온 개정이다. **두 검 모두 크롬이 기본이고 레드는 사건에만 쓴다.**

| 대상 | 평시 | 사건 |
|---|---|---|
| 내 검 | chrome finish. 칼날 emissive는 steel 톤 0.06 | **내가 득점하는 순간에만** 칼날이 red.light로 터졌다 JUDGE 안에 꺼진다 |
| 상대 검 | antique finish. 원본 골동 재질 그대로 | 역사 속 검객이라는 서사를 재질이 진다 |
| 궤적 리본 | **소유 색 유지.** 내 red.light, 상대 blue.light | 명중 코어 #FFFFFF |
| 피격(내가 맞음) | | 파란 연출이 아니라 **FUI 데미지 표시**. 팔각 프레임 가장자리가 red.light로 점등한다. 경고의 레드다 |

칼날에 레드를 상시로 얹으면 레드가 배경색이 되어 득점 순간이 묻힌다. 궤적은 소유 구분이라는 다른 일을 하므로 색을 계속 가진다. **칼날은 크롬, 궤적은 소유 색, 레드 플레어는 사건.** 세 층이 각각 다른 정보를 진다.

## 3. 재질 규칙 (크롬의 사용처)

레퍼런스의 질감을 세 단계로만 허용한다.

1. **크롬 타이포.** 디스플레이 크기 한정. 히어로 제목, 로고, 승패 연출 문구. 날 선 형태감은 시각디자이너 커스텀 레터링 영역이고, 코드에서는 스틸 그라디언트 + 미세한 스큐로 근사한다.
2. **크롬 오브젝트.** brand의 제품 렌더(모의 검 컨트롤러), arena의 검신. 림 라이트를 steel.edge로 잡고 몸체를 steel 그라디언트로 채운다.
3. **사슬 텍스처.** brand 히어로와 포스터 컷에만. UI 배경 반복 패턴 금지, arena 금지. 텍스처가 궤적과 HUD를 잡아먹는다.

유리 질감 liquidGL은 brand 카드 한두 곳에만, Tubes Cursor는 brand 배경에만 쓰고 크레딧을 표기한다. 둘 다 arena 반입 금지.

## 4. 타이포그래피

Pretendard Variable 단일. fallback은 -apple-system, BlinkMacSystemFont, sans-serif.

| 역할 | clamp | weight | tracking | leading | 재질 |
|---|---|---|---|---|---|
| display | clamp(2.5rem, 1.2rem + 6vw, 8.5rem) | 800 | -0.03em | 1.05 | 크롬 허용 |
| title | clamp(1.75rem, 1rem + 3vw, 4.25rem) | 700 | -0.02em | 1.15 | 크롬 허용 |
| heading | clamp(1.25rem, 1rem + 0.8vw, 1.75rem) | 600 | -0.01em | 1.3 | 플랫만 |
| body | clamp(1rem, 0.95rem + 0.2vw, 1.125rem) | 400 | 0 | 1.7 | 플랫만 |
| caption | 0.8125rem | 400 | 0.01em | 1.5 | 플랫만 |
| hud | clamp(0.875rem, 0.8rem + 0.3vw, 1.125rem) | 600 | 0.06em | 1.2 | 플랫만 |

크기별로 tracking과 leading을 함께 조정한다. 간격은 rem 기반으로 사용자 글자 크기 설정을 존중한다. display와 title의 상한은 3840 기준이다. 상한을 낮추면 2560과 3840에서 제목이 작아 보인다. 레퍼런스처럼 날카로운 디스플레이 워드마크가 필요한 자리는 시각디자이너 SVG 레터링 슬롯으로 비워 둔다.

## 7. 모션 토큰

DOM UI는 Apple HIG 기준. 이징은 아래 값을 그대로 쓴다.

```
ease-out     cubic-bezier(0.23, 1, 0.32, 1)     진입, 이탈
ease-in-out  cubic-bezier(0.77, 0, 0.175, 1)    화면 내 이동
ease-drawer  cubic-bezier(0.32, 0.72, 0, 1)     시트, 드로어
thrust       cubic-bezier(0.7, 0, 0.3, 1)       캔버스 전용 찌르기 가속. DOM 금지
```

지속시간: press 100~160ms, tooltip 125~200ms, dropdown 150~250ms, modal 200~500ms, 페이지 전환 크로스페이드 150~200ms(슬라이드업 금지), judge 800ms(게임 전용). DOM UI는 300ms 미만.

스프링 기본 damping 1.0. 이동 1.0/0.4, 회전 0.8/0.4, 드로어 0.8/0.3. press는 :active에 scale(0.97). hover에 scale 금지, 블랙 배경에서는 배경 변화 대신 보더와 글로우(red.glow, line.strong)로 hover를 표현한다.

reduced motion, reduced transparency, prefers-contrast 3종 대응. reduced motion에서 시간 팽창과 대형 화면 모션은 강도를 낮추거나 끈다.

## 9. arena 렌더링 레이어와 성능 예산

**1인칭 three.js가 기본이다.** 3인칭 canvas 2D는 폴백으로 유지한다(삭제하지 않는다).
시점을 1인칭으로 올린 이유는 둘이다. 컨트롤러가 보내는 쿼터니언이 내 검 자세에 1대1로 꽂히고,
궤적 리본과 후처리가 GPU로 넘어가 CPU 예산에 여유가 생긴다.

세부 씬 사양은 `ARENA_SCENE.md`, 입력 분리는 `ARENA_INPUT.md`를 따른다.

### 레이어 (안쪽에서 바깥으로)

1. **배경**: 도장 이미지 평면 + FogExp2(bg.deep 톤). 이미지 도착 전에는 그라디언트 텍스처가 임시로 선다.
2. **AI 상대**: 정면 선수 스틸 빌보드. 몸체는 bg.raised 채움, 외곽은 림. 림 밝기는 Bloom threshold 아래로 묶는다(블룸은 궤적 전유물). 포즈 5종(대기, 전진, 텔레그래프, 런지, 피격)을 평면 2장 크로스페이드로 전환하고 항상 카메라를 향한다. 간합 d를 월드 z로 매핑해 다가오고 물러난다.
3. **내 검**: 화면 오른쪽 아래 그립의 1인칭 검. 검신은 steel 톤 금속 재질, 검끝에 red.light emissive 마커. 키보드는 프리셋 자세 트윈, 컨트롤러는 쿼터니언 직결.
4. **궤적 리본**: 자체 구현(사전 할당 버퍼 제자리 갱신). 내 검 red.light, 상대 blue.light, 명중 코어 화이트를 JUDGE 동안 고정. additive blending에 나이 감쇠.
5. **후처리**: RenderPass → 잔상(SavePass + TextureEffect, damp 평시 0.70) → EffectPass(Bloom, ChromaticAberration, Vignette, HueSaturation) → ShockWave. `postprocessing`에 AfterimagePass가 없어 같은 식을 이 라이브러리 기본기로 세운다.
6. **HUD**: DOM. 이 층만 MOTION 규율이 그대로 적용된다. **XR 글라스 팔각형 프레임**(SVG 한 장, 크롬 스트로크와 red.light 코너 액센트)이 뷰포트를 두르고, 모든 HUD 요소가 컷 크기 + 12px 인셋 하나를 공유한다. 중앙 시야는 비운다. 세부는 `ARENA_SCENE.md` 16절.

### 소유 색

궤적 색은 v2 확정 매핑이다. **내 검 red.light, AI 상대 blue.light, 명중 코어 #FFFFFF.**
v1에 "내 검 블루"로 적힌 것은 폐기분이고 `tokens.trail`이 진실이다.

### 성능 예산

tokens.js motion.budget: targetFps 60, minFps 30, trailMaxSegments 240, particleMax 300, afterimageMax 6, timeDilation scale 0.35 / maxMs 1200 / cooldownMs 8000.

감축 순서는 파티클 → AfterimagePass damp 하향 → Bloom 해상도 하향이다.

### 폴백

Chromium 파생 브라우저의 WebGL 타이밍 차이와 컨텍스트 손실에 대비해 **2D 폴백이 필수다**.
생성 실패, `webglcontextlost`, URL 파라미터 `?renderer=2d` 세 경로 전부에서 2D로 살아나야 하고
StatusChip에 "호환 렌더"를 표시한다. 캔버스 밖 HUD와 버튼은 transform, opacity 규칙과 44px 터치 타깃을 지킨다.

## 10. 모티프

## 12. 앱별 적용

### presentation
편집 감각은 lusion.co 본문 참조. 블랙 무대 위 대형 크롬 타이포와 넉넉한 여백. @bsmnt/scrollytelling, lenis, gsap, SplitText. 스크롤 진행에 따라 궤적이 그려지고 섹션 전환이 찌르기 리듬을 탄다. 구성: 표지, 배경, 인사이트, 컨셉, 인터랙션 4종, AI 워크플로우(툴 로고 나열 금지, AI가 한 것과 사람이 판단한 것 병기), 최종 산출물, 라이브 데모 진입.

### brand
전환 문법 zentry.com 참조. 클립패스 히어로에 크롬 워드마크와 사슬 텍스처. Tubes Cursor 배경(크레딧 표기), liquidGL 카드 한두 곳. 구성: 히어로, 월드빌딩, 제품군 4종, 유파 소개, 체험해보기. 체험해보기 버튼이 arena로 이동한다.

### arena
9절 그대로. 무거운 브랜드 효과 반입 금지, 60fps 사수.

### controller
최소 화면. QR 접속, iOS 13+ 권한 버튼, 캘리브레이션, 방 코드, Wake Lock. 블랙 배경 위 red.fill CTA 하나가 화면의 전부여도 된다. PiyuSX/GameProtoType 로직을 JS로 포팅(코드 복사 금지).

## 13. 접근성

텍스트 대비 4.5:1, 대형과 UI 3:1을 실측으로 만족시킨다. 근거: red.light 5.2:1, blue.light 9.8:1, text.primary 18:1 이상, red.fill 위 흰 텍스트 5.3:1. text.dim(0.55 알파)이 읽히는 하한선이고 그 아래 밝기의 텍스트를 만들지 않는다. 키보드 전 기능 도달, focus-visible 전 요소. 포커스 링은 red.light 2px. 한국어 줄바꿈 keep-all. 색 단독 구분 금지, 라벨 병기. 웹캠과 센서 실패 시 우아한 저하.
