# IA.md 간합 정보 구조

네 앱의 화면 목록과 흐름, 앱 간 연결을 정의한다. ROUTES.md와 1:1이다. 화면 추가와 삭제는 이 문서 수정 후에만 한다. 인증 없음, 사용자 역할 없음. 모든 화면은 공개다.

---

## 1. 앱 간 연결 지도 (이 프로젝트의 척추)

```
presentation 마지막 섹션 [데모 시작] ──→ arena (VITE_ARENA_URL)
brand 제품 상세 [체험해보기]      ──→ arena (VITE_ARENA_URL)
arena PAIRING 화면의 QR           ──→ controller?room=CODE (배포 URL + 방 코드)
controller ⇄ server ⇄ arena       Socket.io 릴레이 (VITE_SERVER_URL)
```

이 네 연결이 끊기면 프로젝트가 셋으로 흩어진다. 환경 변수로만 연결하고 하드코딩하지 않는다.

---

## 2. presentation (단일 스크롤 페이지)

화면은 하나다. 섹션 8개가 스크롤 순서대로 이어진다. 화살표 넘김 금지. 발표 대본과 섹션 순서가 일치한다.

| # | 섹션 id | 내용 |
|---|---|---|
| 1 | cover | 표지. 크롬 워드마크 간합, 한 줄 정의, 스크롤 유도 |
| 2 | background | 배경. Fencing Visualized 계보 언급(자체 제작 비주얼로), 펜싱 훈련의 문제 |
| 3 | insight | 인사이트. 거리와 타이밍 지각이 훈련의 본질이라는 발견 |
| 4 | concept | 컨셉. 간합의 정의, 월드빌딩, 시간 지각 확장 서사 |
| 5 | interactions | 인터랙션 디테일 4종. 블레이드 트래킹, 풋워크 판정, 페인트 판독, 시간 팽창. 하나씩 스크롤 스텝으로 |
| 6 | ai-workflow | AI 워크플로우. 단계마다 AI가 한 것과 사람이 판단한 것 병기. 툴 로고 나열 금지 |
| 7 | outputs | 최종 산출물 3종 소개. brand와 arena 화면 캡처 |
| 8 | demo | 라이브 데모 진입. [데모 시작] 버튼이 arena로 이동 |

고정 UI: 우측 진행 레일(현재 섹션 표시, 클릭 이동), 스크롤 진행에 따라 그려지는 검끝 궤적 라인.

## 3. brand (홈 + 제품 상세 4)

| 화면 | 경로 | 내용 |
|---|---|---|
| 홈 | / | 히어로(클립패스 + 크롬 워드마크 + 사슬 텍스처) → 월드빌딩 → 제품군 4종 카드 → 유파 소개 → 체험해보기 CTA → 크레딧 푸터 |
| 제품 상세 | /products/:key | key 4종: xr-glass(XR 글라스), saber-controller(모의 검 컨트롤러), branding(브랜딩), demo-app(인터랙티브 데모 앱). 히어로 렌더, 스펙 서사, 하단 [체험해보기] → arena. 없는 key는 홈으로 폴백 |

유파 소개는 홈 섹션이다. 데이터는 `src/content/schools.js`(이탈리아 세이버, 프랑스 에페 + 확장 슬롯). 유파별 이름, 리듬 한 줄, 색 표기.

크레딧 푸터: Tubes Cursor(CC BY-NC-SA) 크레딧, 팀 표기.

## 4. arena (단일 화면, 상태가 화면이다)

경로는 / 하나다. 상태 머신의 phase가 곧 화면이다.

| phase | 화면 내용 |
|---|---|
| IDLE | 타이틀, [경기 시작] 버튼, [키보드 모드] 안내(F9) |
| PAIRING | 방 코드 대형 표기 + QR(controller URL + ?room=). 접속 대기 스피너 |
| CALIBRATION | 폰을 검처럼 쥐고 정지 3초 안내. 진행 링. 완료 시 자동 진행 |
| EN_GARDE | 대치. 하단 거리 게이지(유효 범위 밴드 표시), 유파 이름, 점수 |
| EXCHANGE | 공격 교환. 궤적 렌더 활성, 판정 활성 |
| JUDGE | 판정 연출 0.8초. 명중 궤적 흰 코어 고정, 판정 텍스트 |
| SCORE | 점수 반영. 5점 선취 확인 후 EN_GARDE 복귀 또는 MATCH_END |
| MATCH_END | 승패 연출(크롬 타이포), 최종 스코어, [다시], [처음으로] |

상시 UI: 우상단 상태 칩 3개(서버 연결, 컨트롤러 연결, 캠 상태). 캠 거부 시 "시간 팽창 대체 작동" 칩으로 우아한 저하를 드러낸다.

키보드 모드: F9로 즉시 전환. 방향키 전진 후퇴, 스페이스 찌르기, 시프트 가드. 서버가 죽어도 경기는 산다.

## 5. controller (단일 화면, 세로 고정)

경로는 / 하나, ?room= 파라미터로 방 코드를 받는다. phase 순서:

| phase | 화면 내용 |
|---|---|
| JOIN | ?room= 있으면 자동 접속 시도, 없으면 코드 4자리 입력. 접속 실패 사유 인라인 |
| PERMISSION | iOS 13+ DeviceMotion 권한 요청 버튼(사용자 제스처 필수). 안드로이드는 자동 통과 |
| CALIBRATION | 검처럼 쥐고 정지 3초. arena와 동기 진행 |
| PLAY | 폰이 검이다. 화면은 최소: 상단 방 코드와 연결 상태, 중앙 찌르기 판 문구, 하단 스와이프 전진 후퇴 영역. 가드는 폰 세우기 |
| END | 결과 한 줄, [다시] |

햅틱: hit, parry, lose 패턴 수신 시 navigator.vibrate. iOS는 화면 플래시 + 사운드 대체. Wake Lock 상시.

## 6. 데모 플로우 2벌 (발표장 대본과 1:1)

관객 참여 컷: 발표 demo 섹션 → arena IDLE → PAIRING QR → 심사위원 폰 접속 → CALIBRATION → 1라운드.
안전 컷: 팀원 폰 사전 페어링 상태로 arena 대기 → 즉시 EN_GARDE 진입.
비상 컷: F9 키보드 모드 → 발표자 단독 시연. 최후는 녹화 영상.
